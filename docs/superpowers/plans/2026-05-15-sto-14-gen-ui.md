# STO-14 Gen-UI Reader Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add local, schema-driven Gen-UI reader activity cards plus aggregate parent insights without backend/LLM integration.

**Architecture:** Keep Gen-UI isolated in `lib/src/features/gen_ui/` with domain schema parsing, local mock card repository, Riverpod state, and presentation widgets. Reader only consumes a prompt overlay; Settings only consumes aggregate parent insights. Invalid schemas return validation errors/null and never render.

**Tech Stack:** Flutter, Riverpod 2 handwritten providers, existing Storia theme/widgets, `flutter_test`; no codegen and no new backend/LLM dependency.

---

## File Structure

- Create/complete `lib/src/features/gen_ui/domain/gen_ui_card_schema.dart` — whitelisted schema parser/validator and card enums.
- Create `lib/src/features/gen_ui/domain/gen_ui_activity.dart` — immutable activity log/events and aggregate helpers.
- Create `lib/src/features/gen_ui/domain/gen_ui_prompt_policy.dart` — local prompt throttling and card selection.
- Create `lib/src/features/gen_ui/data/gen_ui_activity_controller.dart` — `StateNotifier` for answer/skip/complete events.
- Create `lib/src/features/gen_ui/data/mock_gen_ui_cards.dart` — deterministic local mock cards keyed by reader page/book.
- Complete `lib/src/features/gen_ui/data/gen_ui_providers.dart` — provider family selecting a valid card for `bookId/pageIndex`.
- Create `lib/src/features/gen_ui/presentation/reader_activity_card.dart` — accessible reader overlay/card UI.
- Create `lib/src/features/gen_ui/presentation/parent_insight_cards.dart` — supportive aggregate parent insights.
- Modify `lib/src/features/reader/reader_screen.dart` — mount prompt overlay above reader controls.
- Modify `lib/src/features/settings/settings_screen.dart` — show parent insights near top of Settings.
- Add tests under `test/features/gen_ui/{domain,data,presentation}/`.

## Acceptance Criteria

- Reader can render local schema-driven activity cards for supported schema types.
- Invalid/unsupported schemas fail gracefully and do not crash or render unsafe UI.
- Child skips are neutral: recorded as skipped, never incorrect.
- Emotional/reflection cards are never graded and parent insights use supportive non-diagnostic wording.
- Parent insights aggregate local in-memory interactions without backend/LLM integration.
- `flutter analyze` and relevant Flutter tests pass.
