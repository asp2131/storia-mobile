Migration Overview
This document is your agentic kickoff brief for migrating Storia's React Native / Expo proof-of-concept to Flutter. It is structured to be handed directly to Claude Code or Codex as a phased execution plan. Each phase includes concrete tasks, Flutter package equivalents, and the critical technical context needed to reconstruct the most complex subsystems.

Scope
Two screens: Library Screen + Book Reader Screen. Existing Supabase backend (PostgreSQL, RLS, Storage) remains 100% unchanged. The Flutter app is a new client pointing at the same data layer.

Key Technical Challenge
The text overlay system — percentage-based positioned text elements rendered over illustrations with word-level highlighting, staggered animations, and tap interaction — is the most complex piece and requires careful 1:1 reconstruction in Flutter.

PHASE 1
Project Bootstrap & Data Layer
Days 1–2

Goals
Get a Flutter project running with Supabase connected, go_router configured, and real book data loading. No UI polish — just a working data pipeline.

Tasks
	•	Create Flutter project: flutter create storia_flutter --org com.storia --platforms ios,android
	•	Add all dependencies to pubspec.yaml (see dependency map above)
	•	Configure Supabase in main.dart with SUPABASE_URL and SUPABASE_ANON_KEY from .env
	•	Set up go_router with two routes: /library and /reader/:bookId
	•	Create Riverpod providers: bookLibraryProvider (FutureProvider) and currentBookProvider
	•	Write BookRepository class wrapping Supabase queries
	•	Generate Dart types from existing Supabase schema (mirrors TypeScript types in types/index.ts)
	•	Verify Supabase Storage URLs resolve for book cover images and audio files

Key Supabase Query Pattern
// lib/repositories/book_repository.dart
class BookRepository {
  final SupabaseClient _supabase;

  Future<List<Book>> getPublishedBooks() async {
    final data = await _supabase
      .from('books')
      .select('*, pages(*, overlay), soundscapes(*)')
      .eq('published', true)
      .order('created_at');
    return data.map((j) => Book.fromJson(j)).toList();
  }
}

PHASE 2
Audio Engine
Days 3–5

Goals
Build the AudioEngine abstraction — the most critical infrastructure in Storia. Two simultaneous just_audio players, one for narration, one for soundscape. Page-synced loading, crossfade transitions, background playback, and lock screen controls.

Architecture
Create a single AudioEngine class exposed via Riverpod as a singleton. This class owns both players and exposes a clean interface to the UI layer. The UI never touches just_audio directly.

// lib/audio/audio_engine.dart
class AudioEngine {
  final AudioPlayer _narration = AudioPlayer();
  final AudioPlayer _soundscape = AudioPlayer();

  Future<void> loadPage(PageData page) async {
    await Future.wait([
      _narration.setUrl(page.narrationUrl),
      _soundscape.setUrl(page.soundscapeUrl),
    ]);
  }

  Future<void> play() async {
    await Future.wait([_narration.play(), _soundscape.play()]);
  }

  Future<void> transitionToPage(PageData nextPage) async {
    // Crossfade soundscape, cut narration cleanly
    await _soundscape.setVolume(0);
    await loadPage(nextPage);
    await _soundscape.setVolume(1);
    await play();
  }

  Stream<Duration> get narrationPosition => _narration.positionStream;
  void setNarrationVolume(double v) => _narration.setVolume(v);
  void setSoundscapeVolume(double v) => _soundscape.setVolume(v);
  void dispose() { _narration.dispose(); _soundscape.dispose(); }
}

Tasks
	•	Implement AudioEngine class as above
	•	Configure audio_session for media playback mode (handles call interruptions)
	•	Set up just_audio_background with lock screen metadata (book title, cover art)
	•	Add iOS background audio capability in Info.plist: UIBackgroundModes = [audio]
	•	Add Android FOREGROUND_SERVICE permission in AndroidManifest.xml
	•	Wire AudioEngine into Riverpod as a singleton provider
	•	Expose narrationPosition stream for word highlighting sync (Phase 4)
	•	Preload next page audio while current page is playing (improves transition feel)

Critical iOS Note
Background audio requires both the Info.plist UIBackgroundModes entry AND the audio_session package configured with AudioSession.instance.configure(AudioSessionConfiguration.music()). Missing either one will cause playback to stop when the screen locks — unacceptable for a kids reading app.

PHASE 4
Text Overlay System (Critical)
Days 8–12

Priority Warning
This is the most complex phase. The text overlay system is the core product differentiator — percentage-positioned text elements on illustrations with word highlighting. Rebuild this carefully. Do not rush it.

Overview of Existing System
The React Native implementation uses three key components: PageRenderer.tsx (orchestrator), OverlayTextLayer.tsx (element positioning), and OverlayTextElement.tsx (per-element rendering + word highlighting). The Flutter reconstruction follows the same three-layer architecture.

Data Contract — Unchanged
The PageData.overlay structure from the existing types/index.ts is the source of truth and does not change. Flutter models must map 1:1 to this schema:

// lib/models/page_overlay.dart — mirrors types/index.ts exactly
class PageOverlay {
  final String version;
  final List<TextElement> elements;
}

class TextElement {
  final String id;
  final String text;
  final double x;        // percentage of image width
  final double y;        // percentage of image height
  final double width;    // percentage of image width
  final String fontFamily;
  final double fontSize; // percentage of image HEIGHT
  final int fontWeight;
  final String color;
  final String textAlign;
  final double? rotation;
  final TextShadow? shadow;
  final TextBackground? background;
}

Rendering Architecture — Flutter
The Flutter reconstruction maps directly to the RN architecture using Stack and Positioned widgets instead of absolute positioning.

Step 1: Measure Container (onLayout equivalent)
// Use LayoutBuilder to get container dimensions
LayoutBuilder(builder: (context, constraints) {
  final containerSize = Size(constraints.maxWidth, constraints.maxHeight);
  return PageRendererWidget(containerSize: containerSize, page: page);
})

Step 2: Compute Contained Image Rectangle
This is the Flutter equivalent of computeContainedImageRect() in lib/textOverlay.ts. Must be reconstructed exactly — it calculates letterboxing offsets so text and image share the same coordinate space.

// lib/rendering/text_overlay.dart
Rect computeContainedImageRect({
  required Size container,
  required Size sourceImage,
}) {
  final containerAspect = container.width / container.height;
  final imageAspect = sourceImage.width / sourceImage.height;
  double w, h, x, y;
  if (imageAspect > containerAspect) {
    w = container.width;
    h = w / imageAspect;
    x = 0;
    y = (container.height - h) / 2;
  } else {
    h = container.height;
    w = h * imageAspect;
    y = 0;
    x = (container.width - w) / 2;
  }
  return Rect.fromLTWH(x, y, w, h);
}

Step 3: Stack-Based Overlay Layer
// PageRenderer widget
Stack(children: [
  // Image fills container with contain fit
  Image.network(page.imageUrl, fit: BoxFit.contain, width: double.infinity, height: double.infinity),

  // Overlay layer positioned to match the contained image rect
  Positioned(
    left: imageRect.left,
    top: imageRect.top,
    width: imageRect.width,
    height: imageRect.height,

      elements: page.overlay.elements,

      onWordTap: handleWordTap,
    ),

])

Step 4: Percentage-to-Pixel Conversion (per element)
This is the critical math that keeps text anchored correctly across all screen sizes. Mirrors the existing OverlayTextElement conversion exactly:

// In OverlayTextElement widget
final left = element.x / 100 * imageWidth;
final top = element.y / 100 * imageHeight;
final width = element.width / 100 * imageWidth;
final fontSizePx = element.fontSize / 100 * imageHeight; // NOTE: uses HEIGHT

return Positioned(
  left: left,
  top: top,
  width: width,
  child: OverlayTextElement(
    element: element,
    fontSizePx: fontSizePx,
    imageWidth: imageWidth,
    imageHeight: imageHeight,
    activeWordIndex: activeWordIndex,
    onWordTap: onWordTap,
  ),
)

Step 5: Word Highlighting
Word-level highlighting requires tokenizing each TextElement's text, mapping tokens to global word indices, and applying highlight styles to the active word. The narration timestamp from AudioEngine.narrationPosition drives activeWordIndex.

// Tokenize text into word spans
List<InlineSpan> buildHighlightedSpans(
  String text, int globalStartIndex, int activeWordIndex, double fontSize
) {
  final tokens = text.split(' ');
  return tokens.asMap().entries.map((entry) {
    final globalIdx = globalStartIndex + entry.key;
    final isActive = globalIdx == activeWordIndex;
    return TextSpan(
      text: entry.key < tokens.length - 1 ? '${entry.value} ' : entry.value,
      style: TextStyle(
        fontSize: fontSize,
        color: isActive ? Colors.yellow : resolveColor(element.color),
        fontWeight: isActive ? FontWeight.bold : resolveWeight(element.fontWeight),
        shadows: element.shadow != null ? [resolveShadow(element.shadow!)] : null,
      ),
      recognizer: TapGestureRecognizer()..onTap = () => onWordTap?.call(entry.value, globalIdx),
    );
  }).toList();
}

Step 6: Entrance Animations
Each text element animates in with a staggered delay matching the existing behavior (180ms base + 40ms per element index). Uses flutter_animate:

OverlayTextElement()
  .animate()
  .fadeIn(delay: Duration(milliseconds: 180 + elementIndex * 40))
  .slideY(begin: 0.15, delay: Duration(milliseconds: 180 + elementIndex * 40))

Fallback Mode
When overlay.elements is missing but textContent + imageUrl exist, render a gradient scrim at the bottom of the image and display the text block above it. Use a simple Column with a LinearGradient container. This mirrors the existing fallback behavior in PageRenderer.
